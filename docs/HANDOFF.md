## Принятые продуктовые и методические решения

- **Содержательная часть «Столбика» неприкосновенна без согласования:** последовательность «наглядная модель разрядов (точки/треугольники/сотни) → пробное действие и размен → сопоставление с записью столбиком справа налево → самостоятельная тренировка → самопроверка и рефлексия» (`docs/peterson-methodology.md`) — главная ценность проекта.
- **Принцип подачи задания (общий опыт со «Слово 2.0»):** *одна карточка — одна учебная цель, один понятный вопрос и одно действие ребёнка* (`docs/teaching-presentation-proposal.md`). Помощь доступна всегда (сначала наводящий вопрос БУКа, затем прямая подсказка), ошибка — повод разобрать шаг, а не штраф.
- **Перенос переноса/займа в уроке:** перенос показывается отдельной карточкой и только после неё появляется над следующим разрядом (`src/ui/screens/LessonScreen.test.tsx`).
- **Магазин БУКа:** в «Столбике» оставлен компактный магазин аксессуаров совы БУК. Полный магазин из «Слово 2.0» (техника, ангар, музыка, костюмы-пазлы) пока **не переносится** по прямому решению пользователя.
- **Единая архитектура окружения со «Слово 2.0»:** 4 нижних раздела (`Уроки`, `Темы`, `БУК`, `Родителям`), 4 вкладки в «Родителям» (`Обзор`, `Прогресс`, `Настройки`, `Приложение`), сейф прогресса (снимки, корзина 30 дней, выгрузка/загрузка), передача ссылки через PNG QR-код + «Позови друга», автообновление + ручная кнопка «Проверить обновление».

## Контур проверок

При старте новой сессии:

```sh
npm run pickup
```

Перед PR и слиянием — полный локальный контур (`release:check` сравнивает с актуальным `origin/main`):

```sh
npm run test:release
npm run release:check
npm run typecheck
npm run content:check
npm run test:engine
npm run test:smoke
npm run audit:storage
npm run build
npm run test:boot
```

Отдельно вне контура (если менялись таблицы QR-кодировщика `src/engine/qr.ts`):
`npm i --no-save qrcode jsqr && npm run test:qr`.

Ориентиры прогона:
- `test:release` — 6/6 тестов правил релиза;
- `content:check` — все 13 уровней генерируют валидные примеры и шаги;
- `test:engine` — 12/12 тестов арифметики столбика, разрядов и QR/PNG;
- `test:smoke` — 11/11 UI/смоук-тестов в jsdom;
- `audit:storage` — проверка сохранения профилей, снимков, корзины и резервных копий;
- `test:boot` — `dist/index.html`, `manifest.webmanifest`, `sw.js` на месте, стартовый JS-бандл `< 200 КБ` и содержит тексты приложения.

## Известные грабли (общий опыт «Слово 2.0» и «Столбика»)

- **Пустой экран на проде (`Minified React error #185` в Zustand 5).** Селектор `useAppStore((s) => ...)` никогда не должен возвращать новый объект или массив на каждый вызов (`?? []`, `?? {}`, `.filter(...)`). Zustand 5 передаёт селектор в `useSyncExternalStore` и сравнивает результат по ссылке (`Object.is`). Подписываться нужно на отдельные стабильные поля или константы модуля.
- **Лимит размера стартового JS-бандла в `scripts/test-boot.ts` (200 КБ).** Вторичные экраны (`ProfileScreen`, `LessonScreen`, `TopicsScreen`, `ShopScreen`, `ParentGateScreen`, `ParentScreen`) лениво подгружаются через `React.lazy` в `src/ui/App.tsx`. Не импортировать тяжёлые экраны статически в стартовый чанк.
- **Виртуальный модуль `virtual:pwa-register` в тестах.** В `vite.config.ts` плагин `VitePWA` отключён при `mode === 'test'`. Поэтому `virtual:pwa-register` импортируется в `src/main.tsx` и передаётся в `initPWA(registerSW, onUpdate)`, а `src/platform/pwa.ts` не содержит статического импорта `virtual:pwa-register` и безопасно работает в Vitest/jsdom.
- **Принудительная тёмная тема Android и QR-код.** Мобильные браузеры с принудительным Force Dark могут инвертировать SVG-элементы, превращая QR-код в нечитаемый серый квадрат. Поэтому `src/engine/qrPng.ts` рендерит QR-код как растровую 1-битную PNG-картинку (`data:image/png;base64,...`) — пиксели изображения не перекрашиваются браузером.
- **Пересоздание рабочей копии в песочнице.** Если клон пересоздался от точки форка или стерлись `node_modules`, запускать `npm run pickup`: скрипт безопасно подтянет историю через `git reset --mixed origin/<ветка>` (сохранив страховочную ссылку `refs/pickup-backup/<ветка>` и не трогая рабочее дерево), восстановит зависимости и прогонит проверки.
- **Рассинхрон `package.json` и `package-lock.json` при ручном bump версии.** Ручная правка только `package.json` ломает `npm run release:check`. Всегда использовать `npm version <версия> --no-git-tag-version`.
